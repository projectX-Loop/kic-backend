# 레드팀 리뷰 | 이 설계는 어디에서 무너지는가

## 공격 1. 정제된 입력이 보고서의 신뢰성을 높였다는 걸 어떻게 아는가?

**팀의 주장.** 검증 상태와 원문 위치를 함께 넘기면 작성 단계에서 잘못된 수치 인용이 줄고, 계획자가 요청에 필요한 근거를 찾아 누락을 줄일 수 있다.

**반례.** OPERF 1쪽에서 추출기가 약정액 셀을 읽고 역할만 ‘누적 납입액’으로 붙였다고 하자. 펀드, 기준일, 통화, 배율, 판본, 셀 좌표와 관측값 ID는 모두 유효하다. 실제 납입액과 약정액이 같아 재계산값도 같다. 코드는 공시값과의 차이와 판정 보류까지 정확히 기입한다. 그래도 초안의 “납입액 열을 확인해 계산했다”는 문장은 틀렸다. 인용 링크를 열면 약정액 열이 나온다. 다음 분기에 두 값이 달라지면 같은 오류가 배수까지 바꾼다.

**현재 증거.** 원문 한 행은 이 오류가 숫자 대조를 통과할 수 있음을 보여준다. 현재 작업 트리의 FastAPI 앱과 테스트는 프로세스 상태를 확인하고, 합성 JSON은 기대 배수 1.2를 예시한다. 추출·검증·작성 모듈에는 아직 이 반례를 처리하는 구현이 없다. 정확한 값 기입, 올바른 열 선택, 근거에 충실한 문장 작성 중 무엇이 개선되는지는 열려 있다. [앱](../app/main.py) · [테스트](../tests/test_health.py) · [합성 예시](../samples/synthetic_tvpi.json)

**판별 실험.** 같은 문서로 분기 성과 보고와 정정 영향 보고를 각각 작성한다. ①은 모델이 원문으로 직접 작성한다. ②는 정제 입력과 양식별 고정 템플릿·조회 규칙을 쓰고, ③은 같은 입력에서 Plan–Execute로 조회할 근거와 작성할 절을 고른다. ②와 ③은 작성 모델, 양식, 접근 가능한 근거·도구, 수치와 상태를 기입하는 코드, 평가 과제를 맞춘다. 두 방식의 차이로 계획자의 기여를 본다. ①과 ③의 차이에는 정제와 코드 기입의 효과도 섞인다. 이를 나누려면 ②에서 코드 기입만 끄고 같은 필드를 모델이 옮기는 조건을 추가한다. 정제 자체의 효과는 원문과 정제 입력을 같은 고정 양식·조회 순서로 제공하고 두 조건 모두 모델이 값을 옮기게 해 비교한다.

평가자는 작성 방식을 가린 초안을 정답 행·열과 대조한다. 수치·단위·기준일·판본 일치, 인용이 실제 문장을 지지하는지, 보류를 통과로 쓴 횟수, 필수 근거와 필수 항목 누락을 센다. 같은 요청을 반복해 조회 경로, 호출 비용, 대기 시간과 승인까지 사람이 고친 항목도 기록한다.

**설계 결정.** ③이 ②보다 비싸고 느리면서 필수 근거 회수나 수정량에서 이득이 없다면 분기 성과 보고는 고정 조회로 돌린다. 정정 보고에서도 영향받은 절을 더 잘 찾지 못하면 이전 값을 인용한 절을 고정 규칙으로 조회한다. 열을 잘못 붙인 사례는 앞단 추출 규칙을 고치고 역할과 열의 일치를 시험한다.

## 공격 2. 전처리할 수 있는 입력이 좁다면, 자동화한 업무가 얼마나 남는가?

**팀의 주장.** 지원 문서의 대조·재계산·근거 수집을 맡기면 담당자가 초안을 준비하고 확인하는 시간이 줄어든다.

**반례.** 새 운용사의 스캔본에서 단위는 앞쪽 페이지에만 있고 다음 쪽에는 숫자 행만 이어진다고 하자. 시스템이 단위를 찾지 못해 모두 보류하면 잘못 확정한 값은 0건일 수 있다. 하지만 담당자는 원문을 다시 펼쳐 단위를 찾고 행을 확인하고 계산까지 해야 한다. 팀이 먼저 정답 행을 짚어준 문서만 채점하면 바로 이 일이 평가에서 사라진다.

**현재 증거.** 사람이 찾아낸 표본 행과 합성 입력으로는 전체 접수량 중 몇 건을 보완 없이 처리하는지 알 수 없다. 새 양식용 규칙을 작성한 시간, 예외 검토 시간, 기존 수작업 시간의 비교 기록도 없다.

**판별 실험.** 개발에 쓰지 않은 운용사와 양식을 포함해 접수 목록을 먼저 고정한다. 정제 성공 문서의 항목 정확도는 따로 보고하고, 업무 평가의 분모는 실패·보류를 포함한 전체 접수 문서로 유지한다. 각 건을 ① 승인 전까지 사람의 보완 없이 초안을 만든 건, ② 일부를 자동 처리하고 사람이 누락·오류를 보완한 건, ③ 쓸 수 있는 결과가 없어 수작업으로 처리한 건으로 나눈다. 각 건에서 같은 과업을 기존 방식으로 마치는 시간과 비교해, 실제 검토 시간이 줄어든 건이 전체에서 차지하는 비율을 구한다. 최종 승인, 보류 해소와 수작업 재처리 시간도 포함한다.

새 양식마다 팀이 규칙을 만들고 사람이 정답 행을 표시한 시간을 따로 기록한다. 첫 문서와 반복 접수를 구분해, 해당 양식에서 누적 절약한 시간으로 준비·유지 비용을 회수하는지 본다. 보류율과 보완 시간을 함께 보면 전부 보류한 시스템의 낮은 오류율을 설명할 수 있다.

**설계 결정.** 같은 양식이 반복 접수되고 준비와 예외 검토를 포함해 누적 시간이 줄어드는 범위에서는 ‘지원 양식의 반복 검토 보조’로 성립한다. 효과가 익숙한 양식에만 있고 새 양식에서는 사람이 매번 행을 지정해야 한다면 지원 양식과 수동 접수 조건을 제품 설명에 명시한다. 반복 양식에서도 시간이 줄지 않으면 자동화에 따른 업무 절감 주장을 철회한다.
