# KIC 대체자산 사후관리 에이전트

프로젝트x Loop 팀은 PE 펀드 보고서 PDF에서 투자 지표를 추출하고, Python 코드로 수치를 검증한 뒤 원문 근거가 연결된 보고서 초안을 만드는 서비스를 설계하고 있다. 첫 범위는 펀드 하나, 기준일 하나, PDF 한 건에 공시된 TVPI(누적 납입액 대비 총가치 배수)를 재계산해 대조하는 것이다.

## 담당과 인계

| 담당자 | 담당 범위 |
| --- | --- |
| 이승준 | 표본 PDF 선정, 지표 추출, 원문 위치와 추출값 연결 |
| 권도윤 | ERD 설계, DB 저장 구조, Python 코드로 수치 검증 |
| 성종현 | 검증 결과와 원문 근거를 활용하는 에이전트 및 보고서 초안 |

## 첫 개발 단위

현재 저장소에는 애플리케이션 코드, SQL, 실행·테스트 설정이 없다. 기술 방향은 Python·FastAPI·PostgreSQL이며, 원본 PDF와 파생 파일은 EBS에 보관하고 DB에는 파일 참조와 해시를 기록할 계획이다.

1. 문서 판본에서 검증 결과까지 추적할 수 있도록 아래 ERD 초안을 구체화한다.
2. PDF·OCR·외부 API 없이 예시 값만으로 시험할 수 있는 TVPI 검증 함수를 만든다. 예를 들어 같은 기준과 단위의 합성 입력에서 누적 분배액 30, 잔존가치 90, 누적 납입액 100이면 기대 재계산값은 1.2배다.

추출·검증·보고서를 잇는 워크플로우는 실제 인계 샘플을 확인한 뒤 구현한다.

### ERD 설계 초안

| 테이블 | 역할 |
| --- | --- |
| `fund` | 지표의 대상 펀드 |
| `source_document` | 펀드에 속한 원본 보고서의 식별 정보 |
| `document_version` | 보고서의 특정 판본과 파일 참조·해시 |
| `source_block` | 특정 판본 안에서 근거로 인용할 수 있는 원문 위치 |
| `observation` | 기준일별 공시 항목의 원문 표기, 계산용 값, 통화·배율 |
| `observation_evidence` | 관측값과 이를 뒷받침하는 원문 위치의 연결 |
| `validation_result` | 재계산값, 공시값과의 대조 상태 및 판정 사유 |
| `validation_input` | 검증 결과에 사용한 관측값 ID와 그 역할 |

예를 들어 누적 분배액 셀에 ‘30’, 표 머리글에 ‘USD millions’가 있다면 하나의 관측값에 두 건의 `observation_evidence`를 연결한다. 한 건은 숫자 셀을, 다른 한 건은 같은 판본의 단위 머리글을 가리킨다. 검증 결과에서 `validation_input`의 ‘누적 분배액’ 역할을 따라가면 30이라는 숫자와 백만 달러라는 해석의 근거를 함께 확인할 수 있도록 설계한다.
